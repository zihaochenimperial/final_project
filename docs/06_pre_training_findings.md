# 06 训练前自检记录（合成数据，CPU）

目的：在花 GPU 时间前检查机制是否跑得通。**这不是实验结果**：合成数据极小（512 张、64px、layer3 只有 4×4 特征图）、1–2 个种子、训练在 0.25/0.74 两个平台间不稳定。

## 已发现并修复的缺陷
1. 可学习 1×1 读出层未加入优化器（影响 plain/cutout/multitask/fate_learned 全部基线）→ 已修复，**此前的合成数据对比作废**。
2. 擦除损失在部件不可见的样本上无意义（掩码为空时擦除是空操作）→ 仅对可见样本施加。
3. 擦除损失权重 1:1 且从第一步生效，易使部件滤波器整体死掉 → 默认 0.1 并线性预热。
4. 沉默率在“干净时本就不活跃”的样本上给出假的 0 → 现仅统计干净时活跃的样本。
5. LCMV 输出缺少检测阈值，部件不存在时的噪声过 ReLU 仍非零 → 增加按部件的可学习增益/偏置（线性，不破坏零陷）。

## 已验证
- 零陷约束精确成立：对本部件增益 = 1，对其他部件签名的泄漏 ≈ 1e-6（`tests/test_fate.py`）。

## 未解决（GPU 前的风险）
- 修复后，合成数据上 `fate_learned`（学出的读出 + 擦除损失）干净精度约 0.51，仍低于 multitask（0.74）；
  `fate_region`（LCMV 读出）约 0.26，接近随机，沉默率也不优于基线。
- 可能原因（未验证）：①4×4 特征图太粗，签名/掩码分辨率不足；②LCMV 读出由统计量决定而非梯度学习，骨干与签名/协方差同时漂移；
  ③玩具任务的类别信号来自“哪个部件缺失”，对读出线性假设不友好。
- 结论：**尚无证据表明 FATE 优于基线**。真实 CUB（224px，14×14 特征图）上必须先跑 `plain` 与 `fate_region` 的 R18 对比再决定是否投入全矩阵；
  若 LCMV 读出仍明显劣于 `fate_learned`，需检查签名估计/协方差（例如冻结骨干先估计统计量、增大特征分辨率、改用 layer2+layer3）。
